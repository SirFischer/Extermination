# Changelog

## October 15, 2026
### Changed
- Build system: bumped the C++ standard from `c++17` to `c++26` in `Makefiles/default_vars.mk` (`CFLAGS := -Wall -Werror -Wextra -std=c++26`), matching the project's "use the latest C++ standard" policy. `c++26` is the latest standard the installed toolchain supports — `g++ (GCC) 16.2.1` reports `__cplusplus == 202400` for `-std=c++26` (and its alias `-std=c++2c`). The whole project rebuilds cleanly with `-Wall -Werror -Wextra` at the new standard (zero warnings, so no new deprecations or stricter-rule failures), and the game still launches. The `Yuna` submodule and `Yuna/mfGUI` still pin `c++17`; that is not a problem for linking (see below).
- CI: upgraded the GitHub Actions toolchain so the `-std=c++26` build actually works there. `.github/workflows/makefile.yml` now pins `runs-on: ubuntu-24.04` (instead of the floating `ubuntu-latest`) and installs `gcc-15`/`g++-15` from the `ubuntu-toolchain-r/test` PPA, because the runner's stock GCC 13 cannot compile `-std=c++26` (GCC 15+ is required). The Makefiles hard-assign `CC := g++` (immediate assignment), so `CC`/`CXX` environment variables are ignored and `g++` is resolved from `PATH`; the workflow therefore repoints the `gcc`/`g++`/`cc`/`c++` alternatives at the GCC 15 binaries via `update-alternatives`, which fixes both the main build and the `Yuna` submodule build in one step. A probe step asserts `g++ -std=c++26` yields `__cplusplus == 202400` before the build runs. `actions/checkout` was bumped from `v2` to `v4` and `software-properties-common` added to the dependency install (needed for `add-apt-repository`). Verified end-to-end in a real `ubuntu:24.04` container: the PPA provides `gcc-15 15.2.0-14ubuntu1~24~ppa1`, and the full `make` completes with exit 0, zero compiler diagnostics, and objects stamped `GNU C++26 15.2.0 -std=c++26`.
- Build system: fixed two structural hazards that blocked adding a unit-test harness (see `.squad/decisions/inbox/lead-test-harness-scoping.md` §3).
  - **Source auto-discovery no longer sweeps test files into the game binary.** `Makefiles/default_vars.mk` now excludes any `tests` directory from the `find` that populates `SRCS` (`-not -path '*/tests/*'`). Previously a `src/tests/` directory would have been compiled into `obj/` and linked into `Extermination`, colliding with `src/main.cpp`'s `main()`. The exclusion makes this safe by construction; unit tests should still live in a top-level `tests/` directory outside `src/`.
  - **Added a `main()`-free object seam for future test binaries.** `Makefiles/default_vars.mk` defines `GAME_OBJS_NO_MAIN := $(filter-out obj/main.o,$(OBJS))` so a future test target can link the real game objects alongside a test framework's own `main()` (e.g. `libgtest_main`) without a duplicate-symbol collision. The game build itself does not use this variable.
  - No test files, test targets, or dependencies were added; `make test` is unchanged.
### Added
- Next-wave button now has a 30-second auto-launch countdown. The button label shows the remaining seconds (`Next wave (30s)` … `Next wave (1s)`); if the player does not press it, the next wave launches automatically when the countdown reaches zero. Pressing the button manually still launches the wave immediately and restarts the countdown. The timer only runs between waves (while no enemies are alive) and is paused together with the world while the console is open, so it never ticks during an active wave or while the game is paused.
- Three troubleshooting commands for the in-game console (`Tab`), so runtime state can be inspected from the real terminal instead of only through screenshots:
  - `history [count]` — dumps the console's command history to `stdout`, newest first, with a header and footer. The optional `count` argument limits how many entries are printed (clamped to the history size); a non-numeric argument returns `BAD_ARGUMENTS`. This is the command that makes the console useful for headless troubleshooting, since `Console::AddString` only writes to the in-game text box and never echoes to `stdout`.
  - `stats` — prints a one-shot snapshot of live game state to `stdout`: FPS, frame time, entity count, enemy count, next-wave countdown, and the player's position and velocity.
  - `next_wave` — immediately launches the next wave and reports the resulting enemy count. Documented as a debug/cheat command; it is always registered.
  - Supporting change: `Yuna::Core::Console::GetHistory()` was added as a read-only accessor for the private `mHistory` deque (`Yuna/includes/core/console/Console.hpp`). The existing internal `help`, `clear`, and `bind` commands were left untouched.
### Fixed
- Next-wave button countdown text no longer overflows below the button. The label was wrapping onto a second line because the default character size (30) made the string wider than the button, and the text used a fixed top-left offset. The button is now 230px wide with an explicit character size of 20, and the label is recentered inside the button every frame, so the full `Next wave (NNs)` string stays on one line and inside the button for every countdown value from 30s down to 0s.
- Fixed eight bugs found while scoping the unit-test harness:
  - `Inventory::PreviousItem` unsigned underflow and missing bounds check in `GetSelectedItem` — an empty inventory could index out of bounds; `GetSelectedItem` now returns `nullptr` when there is no valid selection, and `NextItem`/`PreviousItem` handle the empty case explicitly. Wrap-around for non-empty inventories is unchanged.
  - `Map::FitToGrid` pushed foliage into `mBlocks` while range-iterating it, invalidating the loop reference on reallocation. Now iterates a snapshot of the original block count; generated foliage is identical.
  - `Map::GenerateGround` pushed ground blocks while indexing `mBlocks`, and read `mBlocks[i + 1]` one past the end on the final iteration. The growing-size iteration is now explicit and documented (it is load-bearing — it fills the ground downward), and the `i + 1` access is bounds-checked. Generated ground is identical.
  - `WaveManager::NextWave` could spin forever when `rand()` kept picking an unaffordable enemy type; it now picks only among affordable types and breaks when none are affordable. `mBuyingPower` growth is clamped to `uint16_t` max instead of silently overflowing. Wave composition is unchanged for the current enemy dictionary.
  - Removed a dead shader load: `World::InitShader` loaded `assets/shaders/global_lighting.frag`, which never existed and was never called or used. The scene darkening is handled by `post-effects.frag` in `Game`.
  - `Weapon::Shoot` leaked every projectile: raw `new` handed to `ProjectileManager`, which removed pointers from its list without deleting them. `ProjectileManager` now owns its projectiles via `std::list<std::unique_ptr<Projectile>>`.
  - Added direct `<cmath>` includes to files using `M_PI` and other math functions, which previously relied on SFML transitively including it.
